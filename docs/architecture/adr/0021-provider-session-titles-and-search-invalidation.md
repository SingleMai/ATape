# ADR-0021: Provider Session Titles and Search Invalidation

- Status: Accepted
- Date: 2026-09-07

## Context

ADR-0011 made the first root-thread UserMessage the Codex Session title. That fallback is stable, but it discards the shorter outcome title generated by Codex and any later user rename. Codex currently records those display names in `session_index.jsonl`, outside the rollout JSONL files collected as Raw source. The local format is an observed compatibility surface rather than a published provider API, so absence, malformed records, incomplete writes, and future format drift must not stop collection.

A title can change without any rollout byte changing. Canonical Session revisions, Adapter cursors, and the derived Search read model must therefore observe Session metadata independently from Raw progress while preserving deterministic at-least-once replay.

## Considered Designs

### Continue deriving every title from the first prompt

This keeps one source and requires no metadata invalidation, but it presents prompt text as identity and ignores the provider's user-visible title semantics.

### Read Codex's SQLite state database

The database exposes a current Session name, but couples the Adapter to a versioned database filename, schema migrations, and concurrent database access. It is a broader and more fragile Interface than the append-oriented title index.

### Prefer the bounded title index with deterministic fallback

The Adapter can decode the small provider metadata record keyed by root Session ID, retain only the latest valid record, and keep the existing root-prompt derivation when the compatibility source is unavailable.

## Decision

The Codex Adapter uses this title precedence:

1. the latest valid `thread_name` for the root Session ID in `session_index.jsonl`;
2. the first root-thread UserMessage from the bounded Canonical projection scan;
3. `Untitled Codex conversation`.

Titles are whitespace-normalized and bounded before entering Canonical. The Adapter reads at most the most recent 16 MiB of the title index, ignores an incomplete tail and malformed records, and treats a missing index as normal compatibility fallback. The provider title is snapshotted in the in-progress Cursor so every page at one Session revision carries identical metadata.

A valid title record's `updated_at` participates in Session modification ordering and revision derivation. Cursor v3 resets v1 and v2 watermarks once, replaying matching Sessions so existing captures receive provider titles. Raw source and Raw progress remain unchanged because the title index is provider metadata, not conversation content.

Canonical ingestion updates the Session when its newer revision changes the title. It also appends Search projection invalidations for that Session's unchanged Events; Events already inserted or updated by the same batch keep their existing projection change. PostgreSQL permits multiple projection changes for the same Event ingest sequence because Session metadata can legitimately reproject one unchanged Event more than once.

## Consequences

- ATape preserves Codex-generated titles and subsequent user renames without inventing titles itself.
- Older Codex layouts and Sessions without indexed names retain the deterministic ADR-0011 fallback.
- A one-time Cursor migration replays Canonical data but does not duplicate Events or Raw bytes.
- Search remains eventually consistent and reflects title-only changes after the projector processes the new invalidations.
- The title index remains an explicitly tolerant compatibility dependency and may require Adapter updates if Codex changes its local metadata layout.

## Rejected Alternatives

- **Generate titles with an ATape model call**: adds cost, nondeterminism, and a second title authority when the provider already owns the display name.
- **Upload `session_index.jsonl` as Raw conversation data**: mixes cross-Session provider metadata into per-Session Raw history and expands the privacy surface.
- **Update only the Canonical Session row**: leaves denormalized Search documents with stale titles.
