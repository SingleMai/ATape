# ATape v0.5.2: Kimi, CodeBuddy and Grok capture

This release adds official Kimi Code CLI, CodeBuddy Code CLI and Grok Build
Adapters to Tools and updates, alongside Codex, Claude Code and OpenCode. All
seven public packages use version 0.5.2.

## Capture support

- **Kimi Code CLI 0.42.0:** main Sessions and native resume, thought/text content,
  successful/failed tools and per-step usage. Original Project attribution,
  stable identities, Raw policy and recovery use the shared source-capture Host.
  Forks, child agents, compaction, undo and interrupted/retried steps remain
  unsupported. Legacy Python kimi-cli is outside this profile. See
  [Kimi support](../adapters/kimi.md).
- **CodeBuddy Code CLI 2.124.0:** primary Sessions, native forks, retained-history
  compaction, completed foreground Agent families, completed background launches
  and serial background child continuation. Native family and compaction limits
  are recorded in [CodeBuddy support](../adapters/codebuddy.md).
- **Grok Build 1.0.3:** completed root text conversations and headless resume,
  successful/failed file reads, foreground commands and per-turn/model usage.
  Forks, compaction, rewind, background commands and other tools remain outside
  this first profile. See [Grok support](../adapters/grok.md).

The new Adapters require a Server advertising `atape.publication.v1`. Their
native source acceptance was performed on macOS arm64; automated installed
contracts additionally run on Linux. Other native versions/platforms are not
implied by these checks. Kimi's provider responses came from a controlled local
endpoint; this does not establish cloud-model or billing acceptance.

## Upgrade and enable

Use Node.js 24 or newer and install `npm install --global @atape/cli@0.5.2`, then
run `atape`. Upgrade existing official integrations in **Tools and updates**,
then select **Kimi Code CLI** (or another new tool) in **Choose tools to sync**.
Installation alone does not enable capture. Check **Project → Sync details** and
the Web reader for acknowledged history.

The CLI now keeps every business operation inside its interactive console;
previous business subcommands have been removed. `--help`, `--version` and launch
options remain available. Reopening ATape after replacing the CLI refreshes a
running managed Collector before new integrations are activated, preserving
Projects, checkpoints and sync settings. User-stopped sync remains stopped.
The Web sidebar also has simpler navigation. See [setup and upgrades](../cli/setup-and-adapters.md).

## Validation and manual acceptance disclosure

Automated gates cover repository checks, production builds, installable tarballs,
native Adapter/Collector HTTP and PostgreSQL contracts, reader/Search, independent
Raw recovery, dependency/container security, race/fuzz checks and paired restore.
These checks must pass for this candidate before publication. They do not replace
manual staging acceptance. The auth-v1 protocol and 180 days absolute Web Session
lifetime are unchanged.

Staging remains pending. The unverified manual checks are candidate artifact
acceptance, official topology, GitHub Provider staging smoke, official-domain
egress isolation, two-user/two-Team acceptance, WAF/TLS/callback configuration,
operational backup/restore, observability secret sampling, rollback and release
signoff.

On 2026-09-13, the user answered “可以，没有问题。” to the explicit question whether
to publish a new ATape version containing Kimi. Under
[ADR-0048](../architecture/adr/0048-release-request-manual-acceptance.md), this
publication request authorizes the candidate-bound manual-only waiver in
[release evidence](evidence/v0.5.2-manual-waiver.json). Those manual checks are
waived, not passed; automated gates remain mandatory. This release does not
authorize or perform a Server deployment or database migration.
