# ATape v0.4.7: reliable collection and configurable Raw capture

Collection now advances through empty pages, retains bounded Codex checkpoints,
attributes paginated sessions to their Git sources, and discovers active sessions
without repeatedly replaying large archives. Large Codex and Claude conversations
use bounded pages; Raw objects upload independently with bounded concurrency and
transient transport retries. Canonical replay preserves source provenance, and
Codex item revisions no longer conflict with earlier versions of the same item.

Raw capture is configurable in Account and Team settings. Teams choose `force`,
`personal`, or `close`; personal preferences choose `enable` or `disable` and apply
only when the Team uses `personal`. New and existing records default to Team
`personal` and user `disable`, so Raw upload stops by default while ordinary
Canonical conversation collection continues. Only Team Owners can change Team policy.

The CLI enforces the effective policy before uploading, even if an Adapter returns
Raw data. The Server checks policy again when accepting and committing Raw uploads.
Official Adapters advertise `atape.raw-capture.v1`, avoid Raw preparation when disabled,
and can backfill retained local sources after re-enabling. Disabled capture requires
upgrading older Adapters that lack this capability. See [Raw capture](../cli/raw-capture.md).

## Upgrade

```sh
atape upgrade
atape adapters upgrade --all
```

Or install `npm install --global @atape/cli@0.4.7` with Node.js 24 or newer.
The CLI and both official Adapters use 0.4.7. Preserve your ATAPE_HOME and restart
running collectors after a manual npm CLI replacement.

Self-hosted instances need the updated Server and Web and migrations 000012 and
000013 before using the new CLI policy endpoint. Migration 000012 increases Raw
chunk capacity; 000013 initializes the Raw capture defaults described above.
Package publication does not deploy a Server or migrate a database. Disabling
capture does not delete existing Raw archives. On-demand recall, automatic retention,
and archive compression are outside this release.

## Validation and manual acceptance disclosure

Automated repository checks, exact package installation tests, PostgreSQL integration,
security scans, race/fuzz tests and self-host restore gates remain required.

The [staging attestation](evidence/v0.4.7-staging.json) is pending. Real GitHub OAuth,
two-user/two-Team acceptance, official topology and domain egress isolation,
TLS/WAF/callback settings, operational backup/restore, secret-log sampling, rollback,
candidate artifact acceptance and release signoff remain unverified for this release
candidate. Manual acceptance is waived, not passed, under the user's explicit request
to merge to origin/main and publish a new package and the standing
[ADR-0048](../architecture/adr/0048-release-request-manual-acceptance.md) authorization.
Candidate-bound evidence records that request. Automated gates are not waived.

The auth-v1 protocol and the 180 days absolute Web Session lifetime are unchanged.
