# ATape v0.4.2: Keep capturing when another conversation cannot be attributed

Codex and Claude can now capture healthy Project conversations even when a scan
also finds history whose original Git repository cannot be established. The
Collector previously rejected the valid `attribution` diagnostic returned by
both Adapters, aborting the entire page before Canonical or Raw upload.

The Collector now validates diagnostics against the shared Adapter protocol.
Known foreign repositories are excluded; unknown sources are skipped with bounded,
redacted local diagnostics. Healthy history uploads and advances its checkpoint.
Resuming collection preserves progress without duplicate uploads. No unknown or
foreign conversation is assigned to the selected Project, and diagnostics never
enter Canonical, Raw or Search payloads.

## Upgrade

```sh
atape stop
npm install --global @atape/cli@0.4.2
atape start
```

Use the same `ATAPE_HOME` for all commands as the running Collector. This fix is
in the CLI; the v0.4.x Codex and Claude Adapters already produce the supported
diagnostic. Existing registrations and checkpoints remain valid, without resets
or configuration migration. If a Project was disconnected, reconnect it through
`atape` before expecting its history to sync.

## Validation and release status

Regression coverage exercises both Adapters with healthy, foreign and unknown
sources, plus Collector publication, redaction, diagnostic-only pages, checkpoint
resumption and rejection of undeclared diagnostic reasons. The release retains
the blocking CI, package, PostgreSQL, security and self-hosting checks.

The [v0.4.2 staging attestation](evidence/v0.4.2-staging.json) remains pending.
On 2026-09-08, after PR #92 passed CI and Security and merged, the user explicitly
authorized a one-time manual staging waiver for v0.4.2 and package publication.
Acceptance was waived, not passed. The
[candidate-bound record](evidence/v0.4.2-manual-waiver.json) and
[ADR-0043](../architecture/adr/0043-v0.4.2-manual-release-waiver.md) record this
separate decision. All automated gates remain blocking; earlier and future
release waivers are not inherited. Real GitHub OAuth,
two-user/two-Team acceptance, official topology and domain egress isolation,
TLS/WAF/callback settings, operational backup/restore, secret-log sampling,
rollback, candidate artifact acceptance and release signoff remain unverified.

This release does not change the auth-v1 protocol or authentication policy,
including the 180 days absolute Web Session lifetime. The CLI, both Adapters,
Server and Web artifact metadata use v0.4.2. Publishing packages does not deploy
a Server or migrate a database. Network and authentication failures remain job
failures and require separate recovery.
