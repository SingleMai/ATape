# ATape v0.3.1 CLI navigation and recovery

The terminal now follows the user's path from connecting a project to checking
sync and resolving an issue, with fewer menus and less repeated input.

## Welcome and project navigation

- First use opens a single-color pixel-cassette welcome. Returning users go
  directly to their projects; explicit `atape setup` still starts directory entry.
- Project rows show sources and sync state. `/` searches; Tab switches between
  projects and global actions. Search, selection and scroll position survive
  returning from details and refreshing status.
- Directory candidates are visible, including parent directories and Git hints.
  Enter browses a folder; `Use current directory` explicitly starts connection.
  Typing, pasting or navigating before candidates finish loading cannot silently
  connect a directory. Git identity remains repository-based for both Adapters.
- Project settings contain configuration and removal. Notices stay in context,
  and resizing a terminal immediately updates the layout.

## Recovery follows the next action

Authentication failures lead directly to sign-in, including an expired credential
in another project that blocks global sync. Retryable failures explain that a
later background cycle will retry. Persistent failures and skipped conversations
lead with the reason and appropriate recovery details. Normal projects prioritize
opening the Web app.

`Refresh status` reads the latest state without starting or restarting collection.
Project and diagnostics pages retain their context during refresh, and a late
response cannot navigate the user back from another page. Exiting the terminal
keeps background sync running; after a reboot use `atape start`.

## Install and try

Node 24 or later is required:

```sh
npm install --global @atape/cli@0.3.1
atape
```

Existing v0.3.0 source integrations remain compatible with this UI update.
New setup installs only the sources explicitly confirmed by the user. Matching
`@atape/adapter-codex@0.3.1` and `@atape/adapter-claude@0.3.1` packages are included
in the coordinated release; installing another integration does not enable it
for existing projects.

The auth-v1 protocol and existing authentication policy, including the 180 days
absolute Web Session lifetime, are unchanged. Coordinated Server/Web artifact
metadata declares v0.3.1 and minimum CLI v0.3.1. Publishing the npm packages does
not deploy a Server, change an existing Instance's minimum CLI or migrate data.

## Validation and release status

Validation covers application recovery classification, real Node-backed presenter
intents, terminal input and retained viewports, and installed-package PTY flows
for login, Web onboarding, confirmed capture, source changes, background lifetime
and terminal restoration. CI and Security remain blocking before publication.

The [v0.3.1 staging attestation](evidence/v0.3.1-staging.json) is pending. No manual
acceptance or waiver is claimed for this candidate. The historical v0.3.0 waiver
is not inherited. Windows TUI, x64, SSH/tmux, IME and accessibility acceptance
remain pending; reboot persistence is outside this increment.
