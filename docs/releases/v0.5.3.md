# ATape v0.5.3: Automatic CLI and official Adapter updates

This release adds automatic updates for the CLI, background Collector and
already-installed official npm Adapters. The CLI and all six official Adapters
use version 0.5.3. Updates select one completed stable GitHub Release and verify
all seven npm packages at that exact version before preparing an installation.

## Install and enable

Use Node.js 24 or newer and a macOS or Linux terminal. Existing 0.5.2 and older
installations must first run `npm install --global @atape/cli@0.5.3`, then reopen
`atape`; those releases do not contain the automatic updater. Future eligible
releases can then update in the background. Official npm-global installations
using the official npm registry are supported; development builds and other
package managers retain their explicit maintenance path.

Automatic updates are on by default after initialization, including for existing
initialized configurations without an update preference. **Settings → Turn off
automatic updates** saves the preference for this local ATape installation. It
prevents new automatic upgrades; recovery of an interrupted handoff still runs.
Custom, local, archive and URL integrations retain their selected source. Updates
do not install or enable additional tools. See
[setup and upgrades](../cli/setup-and-adapters.md#upgrade-the-cli-and-adapters).

## Update and recovery behavior

An independent updater prepares a version directory and immutable Adapter slots
while collection continues. A successful check schedules the next attempt after
24–30 hours; failures retry with exponential backoff. The final GitHub Release,
created after all packages are verified, opens that version for automatic updates.
An incomplete publication or failed preparation leaves the current runtime usable.

The updater closes admission of new collection jobs and requests cancellation;
it does not wait for all historical collection to finish. Collector exit is
bounded at five seconds after SIGTERM and at most two additional seconds after
SIGKILL. Activation has a 45-second workflow budget and local readiness has a
ten-second limit. After an atomic CLI/Adapter selection, only sync that the user
still wants running restarts from existing checkpoints and account-bound journals.
An already-open console uses the selected runtime when reopened.

Failed startup can restore a retained compatible runtime; interrupted handoffs
can recover on a later CLI or Collector trigger. Manual CLI replacement and
automatic updates share OS-held update ownership. Process death releases locks,
and stale updater plans cannot downgrade a newer installed CLI. Adapter import
preflight runs in an isolated child with a ten-second budget and at most one
additional second for forced exit, leaving the old Collector running on failure.

The CLI declares `atape.runtime.v1` with local state contract
`atape.client.v3-capture.v1`. Incompatible contracts reject unattended activation;
version alignment alone does not make state migration or rollback safe. Workflow
deadlines cannot forcibly cancel a stalled OS filesystem call. There is no boot
or login supervisor, automatic release-directory cleanup, remote log recall or
diagnostic-log upload in this release. Real machine power-loss recovery and an
automatic upgrade against the production registry are not established by the
controlled package tests. See [the update decision](../architecture/adr/0100-managed-automatic-updates.md).

## Other included changes

The Claude Adapter includes capture improvements already integrated on main
since 0.5.2, including recorded thinking projection and continued capture around
supported compaction, Read reinjection and unlinked delegation cases. Supported
native versions, exact evidence and remaining source limits are recorded in
[Claude support](../adapters/claude.md). This release does not extend those limits
by inference from the automatic update mechanism.

## Validation and manual acceptance disclosure

Required automated gates cover repository checks, production builds, the exact
installable tarballs and installed updater/terminal behavior, Collector/Server and
PostgreSQL contracts, dependency/container security, race/fuzz checks, supported
self-host configurations and paired restore. They must pass for this candidate
before publication. Controlled release and npm test Adapters do not establish a
live production-registry upgrade or manual staging acceptance. The auth-v1
protocol and 180 days absolute Web Session lifetime are unchanged.

[Staging evidence](evidence/v0.5.3-staging.json) remains pending. Every manual
requirement below is unverified and waived for publication, not marked passed:

- `candidate-artifacts`: manual acceptance of the candidate artifacts.
- `official-topology`: operation in the official deployment topology.
- `github-provider-staging-smoke`: live GitHub Provider staging smoke.
- `official-domain-egress-deny-smoke`: official-domain egress isolation.
- `two-user-two-team`: two-user/two-Team acceptance.
- `waf-tls-callback`: WAF, TLS and callback configuration.
- `backup-restore`: operational backup and restore.
- `observability-secret-sample`: observability secret sampling.
- `rollback`: operational rollback exercise.
- `release-signoff`: manual release signoff.
