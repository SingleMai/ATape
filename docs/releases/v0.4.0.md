# ATape v0.4.0: Global tools and a simpler terminal workflow

Choose Claude Code, Codex or another installed integration once for this machine.
Connect Projects using that selection, then see their sync outcomes immediately.
New Projects reuse the same tools; global changes preview additions and removals
for every connected Project.

## Terminal experience

- First use follows tools, directory, any missing sign-in/Team choice, one review,
  then Project status. Later launches open the Project list, including when tool
  setup is complete but no Projects have been connected.
- Home offers Add project, Tools and Settings. Tool setup, integration updates,
  accounts and global sync controls have one place.
- Project details prioritize sync outcomes and the relevant recovery action.
  Sync details and disconnection replace the generic Project settings page.
- The theme-color pixel cassette stays visible across the terminal, with compact
  variants for shorter screens. Esc returns; r refreshes status in place.
  Duplicate Back/All Projects rows and Open Project in Web are removed.
- Changed tool selections invalidate an unfinished Project review. Reviewing again
  reads the current selection and retains the chosen Team/name where applicable.
- Git Projects still use repository identity across worktrees and clones for both
  Codex and Claude. Exiting keeps sync running; after reboot use atape start.

## Current configuration

ATape has not launched publicly. This version uses one current configuration
schema, with globally enabled tools and Project registrations stored separately.
There are no Project tool overrides, older configuration readers, automatic
migration, migration-triggered restarts or v0.1 migration commands.

Earlier development configurations are unsupported and are not automatically
rewritten or deleted. To try the new flow independently, use an empty ATAPE_HOME:

```sh
npm install --global @atape/cli@0.4.0
ATAPE_HOME="$HOME/.atape-0.4.0" atape
```

Use that same ATAPE_HOME for subsequent commands. It has separate credentials,
registrations and progress. Stop the prior development Collector with its original
CLI/environment before running another Collector for the same Projects.

Scripts configure tools with atape tools configure --adapter codex --apply,
then use atape setup for Projects. Adapter install/upgrade remain available for
custom and offline packages; installing a package does not enable capture.
Disabling tools or disconnecting a Project retains existing history.

Local validation includes Domain, application and CLI tests, real CLI/Go
end-to-end scenarios, installed-package terminal navigation, browser-login/Team
onboarding, global-tool confirmation and cancellation, and Codex/Claude package
replacement with preserved progress. PR CI and Security checks remain required.

[ADR-0041](../architecture/adr/0041-v0.4.0-manual-release-waiver.md) document this

Real GitHub OAuth, two-user/two-Team acceptance, official topology and domain
egress isolation, TLS/WAF/callback settings, operational backup/restore,
secret-log sampling, rollback, candidate artifact acceptance and release signoff
remain unverified. All automated checks remain blocking.

The auth-v1 protocol and authentication policy, including the 180 days absolute
Web Session lifetime, remain unchanged. Coordinated CLI, Codex, Claude, Server
and Web artifact metadata use v0.4.0. Publishing packages does not deploy a
Server or migrate its database. Windows TUI, x64, SSH/tmux, IME and accessibility
acceptance remain outside this increment; automatic reboot recovery is excluded.
