# ATape v0.5.9: Session analysis and normalized tool identity

This coordinated release contains the CLI and all seven official Adapters at
0.5.9, with matching Web, Server and container metadata. The Authentication epoch
remains `auth-v1`, including the 180 days absolute Web Session lifetime. Unified
release and minimum CLI metadata are 0.5.9. Publication and Server deployment
are separate operations; a v4-capable Server must be deployed before the new
Claude capture packages are advertised.

## Session analysis

Session Analytics derives current authorized Canonical counts, explicit tool
outcomes, child Threads, models and recorded Tokens without Raw access, cost or
productivity inference. Filtered evidence opens the original Event through the
same conditional snapshot. Changed source content requires refresh; pagination
does not combine different publications or legacy inputs.

Analytics v2 adds MCP server/tool and Skill-name reports. The first normalized
source is Claude's explicit MCP namespace and `Skill` tool invocation. Source
Adapters provide bounded identities in the closed ACP extension under Canonical
and publication v4. Missing identities remain unclassified; a completed Skill
tool does not establish successful completion of its requested task. New Web
also accepts older analytics-v1 responses without inventing a missing report.

Identity redaction uses the existing upload policy. Masked names or copied source
values explicitly clear identity, preventing a field-rule bypass or grouping
different secret values under one replacement. Unrelated masked arguments keep
public identities. Malformed Unicode identities are rejected consistently
between TypeScript and Go. Oversized Claude Skill inputs do not create new
identity copies outside the admitted content boundary.

See [Session Analytics](../session-analytics.md),
[v4 ingestion](../api/canonical-ingestion.md#v4-normalized-tool-identity),
[ADR-0120](../architecture/adr/0120-normalized-tool-identity.md) and
[ADR-0121](../architecture/adr/0121-tool-identity-release-transition.md).

Opening a Project while its background status refresh is running now shares
the existing process inspection. Concurrent callers no longer block each other
with a process-lock recovery screen; completed results are reread on the next
inspection. Capture timing, Stop intent and exclusion of other commands retain
their existing behavior.

## Upgrade and recovery boundaries

The journal's actual SQLite format, `atape.client.v3-capture.v2` contract,
update-control v1 and compiled `journal-v7-to-v8` plan remain unchanged. V4 source
recovery metadata uses a v3-compatible closed field plus an independent v4 fact;
new readers restore its effective profile. Actual target parts remain v4 and
frozen bytes are not rewritten during receipt recovery.

Published 0.5.8 active official-Claude upgrade parents cannot decode the candidate
Adapter's v4 declaration. Their automatic and existing in-console update paths
reject it before pause; this release does not claim universal unattended
0.5.8 → 0.5.9 delivery. Such installations require the stopped external CLI
refresh described in [explicit maintenance](../cli/setup-and-adapters.md#explicit-maintenance-and-external-replacement),
then complete bundle selection through the updated CLI. Preserve `ATAPE_HOME`,
credentials, project/tool choices and Stop intent. Resume only after every
configured Instance meets the declared capture prerequisites. Other eligible
installations retain the existing managed discovery path.

If the CLI is already current while eligible official integrations remain older,
Tools and updates exposes **Update matching official integrations for ATape
0.5.9**. This invokes the existing complete-bundle upgrade and preserves stopped
intent. Pinned, local, custom or ahead installations do not trigger a blanket
replacement action.

Pinned, custom, local or nonselected old Adapters are not silently replaced.
Historical sessions acquire identities only after a supported updated Adapter
successfully replays their source. Codex Skill message markers and Claude command
expansion remain outside this tool-invocation report. MCP/Skill-specific source
acceptance currently uses constructed native-format records; a fresh live
execution recording remains unverified.

No database migration is added. Once v4 data is accepted, an older pre-v4 Server
image cannot guarantee Reader compatibility. Preserve the current image and a
fresh paired PostgreSQL/Raw recovery point before rollout; restoring that point
withdraws writes made afterwards.

## Candidate validation and manual acceptance disclosure

The exact frozen candidate must pass fresh repository, installed CLI/Adapter,
genuine historical-reader and upgrade-path, PostgreSQL, dependency/container
security, race/fuzz, self-host configuration and paired restore gates. Existing
0.5.8 or feature-PR results do not attest this release candidate.

[The delivery record](evidence/v0.5.9-delivery.json) binds the completed candidate
CI/Security checks, authorized Server rollout, verified paired backup and
encrypted snapshot, synthetic v4 API/Reader smoke, and completed release workflow.

with that workflow's verified archives and checksums, verified both CDN catalogs
and retained historical descriptors. All eight packages used GitHub Trusted
Publishing; decoded provenance content was checked, without cryptographic
signature verification. The rollout added no schema migration and performed no
data restore. No actual registry-install smoke or fresh live MCP/Skill capture
was performed, and universal unattended 0.5.8 upgrade remains outside this release.
