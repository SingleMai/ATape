# ATape v0.3.0 CLI experience

## Guided setup and Project console

Run `atape` to connect a Project through directory selection, browser sign-in,
Team selection and source review. Confirming starts historical import and ongoing
background sync. Returning users can inspect Projects, manage sources, open the
Web app and recover from errors in the terminal.

Git Projects now use one shared repository attribution contract for Codex and
Claude. Worktrees and clones resolve to the same authoritative Project; unknown
historical identity is reported as partial coverage. Git directories cannot be
registered in a folder-only capture mode.

## Upgrade and online self-test

Node 24 or later is required. Install all three matching packages through the
CLI before resuming an existing Collector:

```sh
npm install --global @atape/cli@0.3.0
atape stop
atape adapters install @atape/adapter-codex@0.3.0
atape adapters install @atape/adapter-claude@0.3.0
atape
```

New users can install only the CLI and let guided setup install the sources they
confirm. Existing users should upgrade only the integrations they use; package
installation alone does not enable capture for another source. The new Host
rejects older Git Adapters that do not declare the shared attribution capability.
Existing Config v2 registrations and recognized Adapter checkpoints remain
readable. Exiting the console keeps the Collector running; after a reboot,
run `atape start` manually.

The npm packages can connect to an existing auth-v1 Instance. The coordinated
v0.3.0 Server/Web build metadata retains `auth-v1` and declares minimum CLI
v0.3.0. Publishing npm packages does not deploy the Server or migrate a database.
The existing authentication policy, including the 180 days absolute Web Session
lifetime, is unchanged; v0.1 installations still require the documented
[v0.2 authentication cutover](v0.2.0.md).

records installed macOS/Linux arm64 checks, local live-account setup through
final review, controlled login and nonempty CLI/Go Canonical/Raw/Search checks.
Repository CI and Security remain required. Windows TUI, x64, SSH/tmux, IME and
accessibility acceptance remain unverified; reboot restoration is out of scope.
