# ATape v0.5.8: Static update discovery and bounded Collector handoff

This coordinated patch contains `@atape/cli` and all seven official Adapters
at 0.5.8. It includes the static discovery work from
[PR #223](https://github.com/SingleMai/ATape/pull/223) and the Collector stop-probe
fix from [PR #222](https://github.com/SingleMai/ATape/pull/222).

The Authentication epoch remains `auth-v1`, including the 180 days absolute Web
Session lifetime. Unified artifact release and minimum CLI metadata are 0.5.8.
Package publication does not deploy a Server or change an existing Instance's
minimum CLI version.

## Changes and delivery

New clients discover complete release bundles from `https://updates.atape.net`
through Cloudflare Workers Static Assets. The v1/v2 catalogs and immutable exact
descriptors use the existing domain protocols; npm still serves package archives.
The serialized publisher validates every advertised public package byte, retains
historical exact descriptors and refuses catalog regression or immutable changes
before deploying one complete static snapshot.

Discovery reuses a validated catalog for 12 hours and reuses immutable exact
bundle receipts. Expired verified catalogs can serve a compatible target during
transport failure; malformed metadata, damaged local state and integrity failures
remain errors. Transient metadata requests can retry at most three times within
one ten-second request budget, with cancellation and short `Retry-After` support.
Using stale discovery retains the durable retry schedule even when that cached
target successfully upgrades; it does not reset to a daily success schedule.

Collector stop probes now reject cancelled, late, empty or partial timeout output
as proof of exit. A live PID remains distinct from confirmed exit, and force
termination requires a fresh ownership check. Closing timed-out probe readers
prevents an inherited pipe from extending the bounded handoff. These changes do
not authorize signals to a process whose ownership cannot be confirmed.

Capture contract `atape.client.v3-capture.v2`, update control
`atape.update-control.v1` and the compiled
`atape.capture-migration.v1 / journal-v7-to-v8` plan are unchanged. Existing
0.5.7 clients discover this complete release through the retained GitHub bridge;
the new selected generation then uses the CDN. That initial old-client discovery
can still be delayed by GitHub availability or its existing due schedule. Deploying
static files alone does not replace installed binaries or make immutable 0.5.3
cross its unsupported initial state boundary.

See the [automatic update guide](../cli/setup-and-adapters.md#automatic-updates),
[explicit migration guide](../cli/setup-and-adapters.md#explicit-capture-migration)
and [static publication contract](../releasing.md#static-update-distribution).
Existing provider and Server prerequisites, including experimental
[Cursor requirements](../adapters/cursor.md), remain unchanged.

## Candidate validation and manual acceptance disclosure

The frozen 0.5.8 candidate must pass repository, installed CLI/Adapter, historical
client and migration, PostgreSQL, dependency/container security, Go race/fuzz,
self-host configuration and paired restore gates before publication. Preparing
these notes claims no 0.5.8 CI, npm publication or native unattended upgrade result.
The [0.5.6 → 0.5.7 acceptance](v0.5.7.md#unattended-upgrade-acceptance-and-a-stop-defect)
and [static distribution evidence](evidence/static-update-distribution-20261011.json)
retain their recorded scope; they are not a 0.5.7 → 0.5.8 delivery attestation.

[Staging evidence](evidence/v0.5.8-staging.json) remains pending. All ten manual
checks are unverified and waived for publication only:

- `candidate-artifacts`: manual candidate artifact acceptance.
- `official-topology`: the official deployment topology.
- `github-provider-staging-smoke`: live GitHub Provider staging smoke.
- `official-domain-egress-deny-smoke`: official-domain egress isolation.
- `two-user-two-team`: two-user/two-Team acceptance.
- `waf-tls-callback`: WAF, TLS and callback configuration.
- `backup-restore`: operational backup and restore.
- `observability-secret-sample`: observability secret sampling.
- `rollback`: operational rollback exercise.
- `release-signoff`: manual release signoff.

On 2026-10-11 in Asia/Singapore, the user explicitly requested:

authorizes the candidate-bound manual-only waiver; automated gates remain
