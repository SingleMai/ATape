# ATape v0.5.0: OpenCode local history

OpenCode joins Codex and Claude in the ordinary Tools selection, installation,
upgrade and background collection flows. The Adapter reads local SQLite history
through the Host's bounded Collector. Complete Canonical revisions become visible
atomically; Raw capture follows its own policy and can recover independently.
Restart recovery uses frozen delivery bytes and actual receipts. Package upgrades
preserve collected history and checkpoints.

## Upgrade and enablement

After publication, install `npm install --global @atape/cli@0.5.0` with Node.js 24
or newer, or run:

```sh
atape upgrade
atape adapters upgrade --all
atape
```

In **Tools and updates**, add OpenCode to the current selection and review the
affected Projects. Existing selections are preserved. Installing an Adapter alone
does not enable capture. The CLI and all three official Adapters use 0.5.0.
Preserve ATAPE_HOME and restart collectors after a manual npm CLI replacement.

The receiving Server must expose `atape.publication.v1` with reviewed publication
limits. The CLI supplies collection limits automatically. Self-hosted operators
can opt in with `compose.publication.yaml`; the base Compose configuration leaves
publication disabled. Follow the [rollout procedure](../operations/opencode-rollout.md)
before starting the new Server: startup automatically applies missing migrations,
including 000015–000019 when upgrading from the v0.4.8 schema. This release raises
the advertised minimum CLI version to 0.5.0. Package publication, Server deployment
and database migration require separate authorization; this candidate preparation
performs none of them.

## Supported source and limits

- OpenCode **1.18.30 local v1 SQLite**, on **macOS arm64** and **Linux arm64/glibc**.
  Other source versions, architectures, v2/mixed databases, JSON-only history and
  remote OpenCode servers have no support claim in this release.
- Original creation evidence determines Project attribution, including Git
  worktrees. Later source directory changes do not move captured Sessions.
- Source reads preserve database and WAL content; SQLite may update SHM metadata.
  Unknown parts and unsupported media retain explicit partial fidelity.
- Admission limits are independent ceilings, not guarantees about history size,
  memory or physical disk usage. Oversized sources fail explicitly while retaining
  already published history. Raw-off does not save full source JSON for later
  archival. Re-enabling Raw does not rewrite existing Event provenance.

See the [feature guide](../adapters/opencode.md) for the implementation, native
compatibility evidence and remaining scope. The publication deployment example
is a review starting point, not a production capacity promise.

## Validation and manual acceptance disclosure

Required automated gates cover repository checks, exact installation of the four
release tarballs, installed CLI/Adapter upgrades through real HTTP/PostgreSQL,
dependency/container security, race/fuzz checks and paired backup/restore. The
restore rehearsal enables publication and uses a custom Raw volume through
multiple Compose overrides, verifying that both helpers preserve the deployment
topology.

Native OpenCode 1.18.30 source evidence was gathered with the preceding 0.4.8
candidate artifact on macOS arm64 and Linux arm64/glibc. It compares controlled
native DB/API/CLI output with the installed Adapter; it uses no personal history.
This release changes coordinated package metadata, not the Adapter implementation.
Native runs are distinct from the release's exact-package and installed-CLI tests.

The [staging attestation](evidence/v0.5.0-staging.json) remains pending. Unverified
manual checks are candidate artifact acceptance, official topology, GitHub Provider
staging smoke, official-domain egress isolation, two-user/two-Team acceptance,
WAF/TLS/callback configuration, operational backup/restore, observability secret
sampling, rollback and release signoff. Local automated rehearsals do not establish
operational acceptance for a deployed instance.

Manual staging acceptance is waived, not passed, under the user's response
“fa” (发, publish) to the explicit request to publish the 0.5.0 CLI and the
Codex, Claude and OpenCode Adapters. Under
[ADR-0048](../architecture/adr/0048-release-request-manual-acceptance.md), that
publication request authorizes the candidate-bound manual-only waiver recorded
in [release evidence](evidence/v0.5.0-manual-waiver.json). The checks above remain
unverified; automated CI, integration tests and security gates remain mandatory.
This authorization does not deploy the Server or migrate a database.
The auth-v1 protocol and the 180 days absolute Web Session lifetime are unchanged.

## OpenCode first-publication provenance

At the user's explicit direction, `@atape/adapter-opencode@0.5.0` is bootstrapped
from the already authenticated local npm account using the exact verified tarball.
That package version has no GitHub build provenance attestation. Its SHA-256 is
`1443463999a57ecdb27a9edbe9e02247252c97d3e1add7eb1b3219bad7a77216`.
The regular release workflow verifies its registry integrity and publishes CLI,
Codex and Claude with provenance. All automated checks remain required.

one-version exception is recorded in
[ADR-0077](../architecture/adr/0077-opencode-local-first-publication.md).
