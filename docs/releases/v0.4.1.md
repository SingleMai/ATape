# ATape v0.4.1: Find projects faster and recover sync directly

The Project list now highlights `[n] Add project` above the rows. Press n to add
another project without first navigating the global action bar. Shortcuts remain
ordinary text while searching the list.

## Find a local project by name

In directory browsing, type a name fragment to fuzzy-search nearby folders.
Matching ignores case and allows gaps, including Unicode names. Ranked results
show their full paths to distinguish namesakes. Enter browses a result, then
Use current directory proceeds to the existing connection review. Esc clears
search first; pasting an absolute path replaces the input.

Search covers up to three levels below the current directory, skips hidden and
dependency folders, symlinks and repository interiors, and returns up to 30
results within a bounded scan. Browse upward or paste a full path for projects
outside that scope. This is local directory discovery, not server Project search.

## Simpler tool selection and recovery

Choose tools to sync opens the global checkboxes directly. Save returns to the
originating page, with an impact review only for changed selections affecting
connected projects. The extra Tools and per-tool detail menus are removed.

Project recovery explains which conversations could not sync and offers a direct
action. Missing readers can be installed; incompatible output can prompt an
ATape reader update. Ordinary read errors retain their retry classification,
and sign-in blockers take precedence. Technical errors remain in Sync details.
The ambiguous Fix Claude Code/Codex actions are gone.

Reader maintenance preserves global tool selection, registrations and checkpoints.
A running Collector is not restarted; it reads the replacement on a later cycle.
The UI retains the last observed sync result until that happens rather than
claiming an update proves successful sync.

## Install and try

```sh
atape stop
npm install --global @atape/cli@0.4.1
atape
```

Use the same ATAPE_HOME as your v0.4.0 session for all commands. The current
configuration schema is unchanged; existing v0.4.0 configuration can be used
directly. Older unsupported development schemas are not migrated or rewritten.
After launch, start sync from the home page if it is stopped.
