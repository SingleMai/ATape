# ATape v0.5.5: Shared client redaction and Privacy rules

The CLI and all six official Adapters use version 0.5.5. This release adds one
shared Redaction Module before Canonical and Raw submission and before retaining
source diagnostics, persistent global custom rules, local file testing and an
interactive Settings editor. The auth-v1 protocol and 180 days absolute Web
Session lifetime are unchanged.

## Install and update

Use Node.js 24 or newer and a macOS or Linux terminal:

```sh
npm install --global @atape/cli@0.5.5
```

0.5.4 and 0.5.5 declare the same `atape.runtime.v1` and
`atape.client.v3-capture.v2` contracts. The existing compatible update flow
prepares the CLI and eligible installed official registry Adapters at one exact
release version, preserves Project/tool selections and custom installation
sources, and retains the user's saved Start/Stop intent. Update activation must
commit before new collection jobs can write policy-bound capture state.

The compatible managed-runtime update can provide Settings → Privacy rules
through the existing 0.5.4 interactive npm bootstrap. Install the new npm CLI
with the command above to use `redaction-test`: the 0.5.4 or older bootstrap
checks arguments before delegation, so updating only its managed runtime cannot
add this command. Refreshing the global npm installation updates that entry
point as well as providing the new console.

0.5.3 or older remains a separate manual v1-to-v2 transition. Stop sync using the
old CLI, finish interrupted update recovery, close old consoles and keep a
consistent local-state backup before installing outside the old console. Follow
the [explicit upgrade and recovery guide](../cli/setup-and-adapters.md#upgrade-the-cli-and-adapters).
Do not describe this cross-contract transition as an unattended update, or
downgrade migrated/adopted capture state to a v1 runtime. Manually selecting an
older binary also does not provide this release's redaction guarantees.

The coordinated artifact contract records release version and minimum CLI
version 0.5.5. That minimum is enforced by a future deployment of the 0.5.5 Server
artifact; it is distinct from the compatible local v2 update contract. This
package release does not deploy the Server, migrate a database or change an
existing Instance's advertised minimum CLI. Claude still requires the Server
publication-v2 and legacy-adoption capabilities described in the
[Claude guide](../adapters/claude.md).

## Redaction and global custom rules

The shared Module adapts Confab's 34-rule credential catalog and retains existing
ATape patterns. It covers credential formats such as cloud/service tokens,
private keys, Git credentials, JWTs, password-bearing URLs and credential
assignments. Built-in protection is always on; custom rules add protection.
Configured environment literals remain supported without putting their resolved
values into policy metadata or reports.

Custom rules support RE2 `pattern`, JSON-field-name `field_pattern`, optional
`capture_group` and replacement `type`. Arrays, JSON escapes and valid nested JSON
TEXT use the same transformation. Duplicate decoded keys, masked-key collisions,
invalid rules and exhausted bounds fail safely instead of returning unmasked
content. Canonical identity/correlation fields stay stable; Raw fields remain
content even when named `id`.

Settings → Privacy rules lists, adds, edits, deletes and validates global custom
rules before a default-Cancel save review. Literal editing preserves regular
expression backslashes, and advanced JSON-encoded editing preserves line breaks
and control characters. Invalid expressions remain editable; malformed files
are preserved for repair. Failed or stale saves retain the draft. Inspect and
validate do not create files; confirmed save atomically replaces only the selected
owner-only configuration file. It does not start or stop collection.

The console displays its selected configuration path and environment-literal
count, never literal values. A background Collector can inherit a different
environment. Saved rules apply to its next job only when it selects that same
file; changing its inherited environment requires restarting it. A running job
keeps its immutable policy snapshot.

## Test a standard-format sample locally

```sh
atape redaction-test sample.jsonl
atape redaction-test sample.txt --format text --config ./redaction.json
```

The command prints only masked content to stdout and safe rule counts to stderr.
It requires no sign-in or real provider session and performs no upload, Collector
state/key creation, checkpoint advancement or publication reservation. It tests
the supplied UTF-8 sample, not complete session coverage or final wire bytes.
See [configuration, supported content and limits](../cli/redaction.md).

## Policy changes and recovery limits

Collection binds the effective policy to comparison, frozen capture and Raw
reuse using an installation HMAC identity. Preserve the Collector's
`.redaction-key` and `.redaction-key.json` binding with its state. Missing,
corrupt or replaced established identity fails closed; deleting progress is not
a recovery procedure.

New content cannot resume under a changed policy using earlier sealed bytes.
Source capture reconciles actual receipts before abandoning unactivated
candidates or cancelling unacknowledged Raw obligations and preparing available
sources again. Confirmed accepted history stays historical; it is not
retroactively deleted or re-redacted. Unknown remote outcomes remain pending.
Legacy paged delivery pauses when its uncertain prior request cannot be safely
reconciled. Preserve sources and progress rather than resetting them.

Binary image, audio and resource bodies are not decoded or inspected. Complete
session preview, project overrides, disabling built-in protection, historical
re-redaction/deletion and OCR/audio inspection are outside this release.
Pattern matching can miss uncovered formats; use standard-format samples to
verify the rules you depend on. Confab and RE2JS MIT attribution ships in the CLI's
`THIRD_PARTY_NOTICES.md`.

## Validation and manual acceptance disclosure

Automated publication gates remain mandatory for this exact candidate:
repository checks, production builds, installed checksummed tarballs and
updater/login/PTY behavior, authenticated HTTP/PostgreSQL and historical Adapter
contracts, dependency and container security, Go race/fuzz, supported self-host
configurations and paired restore. Standard Canonical, Raw and diagnostic
contracts are the redaction acceptance surface; no provider-specific session
preview is required. Published-baseline upgrade acceptance uses the unmodified
0.5.4 npm package and covers compatible candidate activation, preserved synthetic
v2 checkpoints and Stop intent, Settings reachability through the old bootstrap,
its rejection of `redaction-test`, and command reachability after a real npm
replacement in an isolated global prefix. Release/npm acquisition is controlled
locally; this does not claim live unattended public-service or provider-session
acceptance. Its evidence must identify the exact downloaded old bytes separately
from synthetic compatible-update fixtures.

[Staging evidence](evidence/v0.5.5-staging.json) remains pending. Every manual
requirement below is unverified and waived for publication, never marked passed:

- `candidate-artifacts`: manual acceptance of the candidate artifacts.
- `official-topology`: operation in the official deployment topology.
- `github-provider-staging-smoke`: live GitHub Provider staging smoke.
- `official-domain-egress-deny-smoke`: official-domain egress isolation.
- `two-user-two-team`: two-user/two-Team acceptance.
- `waf-tls-callback`: WAF, TLS and callback configuration.
- `backup-restore`: operational backup and restore.
- `observability-secret-sample`: observability secret sampling.
- `rollback`: operational rollback exercise.
- `release-signoff`: manual release signoff.

Real logout/login, machine reboot, power loss, native-launched conversation
delivery and Linux Collector/user-manager cgroup lifecycle have not been
manually accepted for this candidate. Automated controlled native-command and
isolated lifecycle checks do not replace these operational exercises.
