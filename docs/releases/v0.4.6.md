# ATape v0.4.6: CLI device status

Settings → atape-cli shows device names, CLI versions, sync health, and installed
Adapter package names and versions. Expand a device for synchronization details,
update guidance and the existing confirmed disconnect action. Multi-project results
retain failures and never-synced projects rather than hiding them behind healthy jobs.

The local collector reports bounded account-scoped status approximately every 30
seconds. Reports older than two minutes are explicitly stale. Version discovery is
best effort; unknown checks are not labeled current. Web status does not provide a
remote command channel. Update and troubleshoot through the local CLI.

## Upgrade

```sh
atape upgrade
atape adapters upgrade --all
```

Or install `npm install --global @atape/cli@0.4.6` with Node.js 24 or newer.
The CLI and both official Adapters use 0.4.6. Preserve your ATAPE_HOME. Restart running
collectors after a manual npm CLI replacement so they use the new reporter.

A separately deployed updated Server/Web is required to expose the dashboard. Apply
migration 000011 before starting the updated Server. Older clients remain supported;
missing metadata is shown as unknown. Multiple logins appear as separate devices.
Package publication does not deploy a Server or migrate a database.

## Validation and manual acceptance disclosure

Automated repository checks, exact package installation tests, PostgreSQL integration,
security scans, race/fuzz tests and self-host restore gates remain required.

The [staging attestation](evidence/v0.4.6-staging.json) is pending. Real GitHub OAuth,
two-user/two-Team acceptance, official topology and domain egress isolation,
TLS/WAF/callback settings, operational backup/restore, secret-log sampling, rollback,
candidate artifact acceptance and release signoff remain unverified. Manual acceptance
is waived, not passed, under the user's explicit publication request and standing
[ADR-0048](../architecture/adr/0048-release-request-manual-acceptance.md) authorization.
Candidate-bound evidence records that request; future publication requests do not
need an additional version-specific waiver confirmation.

The auth-v1 protocol and policy, including the 180 days absolute Web Session lifetime,
are unchanged.
