# ATape v0.4.4: Upgrade from the CLI

ATape now checks for a newer release before opening the welcome, Project list
or setup flow. When a newer version is available, choose **Upgrade and continue**
or **Skip**. Successful checks are cached for 12 hours; offline or failed checks
proceed normally. Skip applies to the current session. Scripts and JSON output
never receive an interactive update prompt.

`atape upgrade` updates the active npm global CLI installation, verifies the
installed executable and restarts previously running background sync with its
original interval and concurrency. Interactive upgrades reopen the new CLI with
the original arguments, directory and ATAPE_HOME. Stopped sync stays stopped;
Project registrations, credentials and checkpoints are preserved.

Cancellation waits for installer termination before releasing its lock. Reopening
ATape relinquishes the old process's keyboard input. When installation succeeds
but sync cannot resume, retry restores sync without reinstalling; Skip opens the
new CLI with sync stopped. Other package managers must use their own update path.
Adapter upgrades remain separate (`atape adapters upgrade --all`).

## Install this release

Versions through v0.4.2 do not yet provide the upgrade command. Install v0.4.4 once
with npm to use it for future releases:

```sh
atape stop
npm install --global @atape/cli@0.4.4
atape
```

Use the same ATAPE_HOME as the running Collector. If sync was running before the
manual installation, run `atape start` to resume it. Node.js 24 or newer is
required. This release also retains the v0.4.2 fix that lets healthy conversations
sync when another source cannot be attributed to a Git Project. No historical
configuration migration or compatibility layer is added.

## Validation and manual acceptance disclosure

Automated checks cover the repository, browser interactions, CLI/Go end-to-end
capture, exact CLI/Codex/Claude tarballs, PostgreSQL integration, dependency and
container scans, Go race/fuzz, self-hosting topology and paired restore. Upgrade
regressions include cancellation of a SIGTERM-resistant installer, installation
lock exclusion, real terminal input after restart and repeated sync recovery.
Every automated test and security gate remains required before publication.

The [v0.4.4 staging attestation](evidence/v0.4.4-staging.json) remains **pending**.
On 2026-09-08 the user explicitly authorized a one-time v0.4.4 manual staging
waiver and package publication. Acceptance was **waived, not passed**. The
[candidate-bound record](evidence/v0.4.4-manual-waiver.json) and
[ADR-0045](../architecture/adr/0045-v0.4.4-manual-release-waiver.md) document this
decision. Real GitHub OAuth, two-user/two-Team acceptance, official topology and
domain egress isolation, TLS/WAF/callback settings, operational backup/restore,
secret-log sampling, rollback, candidate artifact acceptance and release signoff
remain unverified. Previous and future releases do not inherit this waiver.

The CLI, both first-party Adapters, Server and Web artifact metadata use v0.4.4.
The auth-v1 protocol and policy, including the 180-day absolute Web Session
lifetime, are unchanged. Publishing packages does not deploy a Server or migrate
a database. Self-upgrade currently targets the active npm global installation
and the selected ATAPE_HOME; it does not manage Collectors in other homes.
