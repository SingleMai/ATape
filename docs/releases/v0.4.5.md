# ATape v0.4.5: Tools and updates

The global **Tools and updates** page shows the installed and latest versions
of ATape and its official Codex and Claude Code conversation sync integrations.
Select an available update directly. Successful checks are cached separately
for 12 hours; **Check again** refreshes them immediately. Offline checks preserve
installed version information and leave navigation and tool selection available.

Official integrations installed from a local file or custom URL are marked
explicitly. **Use published … integration** replaces that source with the exact
reviewed npm release and records the registry source for future updates. This
fixes the journey where upgrading the CLI left an old development-linked Codex
integration unable to identify Git repositories. Custom publisher packages
remain on their original update path; newer installed releases are not downgraded.

Projects with incompatible integration output now link to tool updates. If sync
is stopped, Project details also offer **Start sync for all projects**. Package
maintenance preserves Projects, enabled tools and capture checkpoints. Running
sync loads replacement integrations on a later attempt; installation alone does
not establish that an earlier sync error is resolved. Stopped sync stays stopped.

CLI upgrades remain available after skipping the startup update prompt and reuse
the existing verified install, terminal restart and sync recovery workflow.
Cancelled integration installation waits for npm termination before releasing
the configuration lock. Stale update selections require another version check.
As before, npm installation does not provide atomic rollback.

## Install and use

From v0.4.4, run:

```sh
atape upgrade
atape
```

Alternatively, install the release with Node.js 24 or newer:

```sh
npm install --global @atape/cli@0.4.5
atape
```

Use the same ATAPE_HOME as your existing installation. Open **Tools and updates**
to review and update any older integration, including one installed from a local
development directory. If background sync was running during a manual npm CLI
replacement, stop it before replacement and restart it afterward. No historical
configuration migration or compatibility layer is introduced.

## Validation and manual acceptance disclosure

Automated gates remain required: repository and browser checks, CLI/Go capture,
exact CLI/Codex/Claude tarball installation and terminal interaction, PostgreSQL
integration, npm/Go and container security scans, Go race/fuzz, self-hosting
configuration and paired restore. Update regressions cover cache expiry, invalid
metadata, local-source replacement, custom publishers, stale selections,
cancellation lock lifetime and CLI upgrade after startup Skip.

The [v0.4.5 staging attestation](evidence/v0.4.5-staging.json) remains **pending**.
Real GitHub OAuth, two-user/two-Team acceptance, official topology and domain
egress isolation, TLS/WAF/callback settings, operational backup/restore,
secret-log sampling, rollback, candidate artifact acceptance and release signoff
remain unverified. The v0.4.4 one-time waiver does not apply to this candidate;
publication requires completed staging or a separately authorized v0.4.5 waiver.

The CLI, both first-party Adapters, Server and Web artifact metadata use v0.4.5.
The auth-v1 protocol and policy, including the 180 days absolute Web Session
lifetime, are unchanged. Package publication does not deploy a Server or migrate
a database.
