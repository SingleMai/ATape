# ATape Adapter 接入

按当前请求推进调研、实现或交付；调研请求以方案和待决问题结束，实现请求继续完成所承诺的接入范围。

以下链接相对本 skill；命令和代码路径以所属 ATape checkout 的根目录为准。读取适用的 [AGENTS.md](../../../AGENTS.md) 和 [Adapter 合同](../../../docs/adapters/package-manifest.md)。架构规则、协议和数值限制以当前文档、Schema 与代码为准。

## 1. 确定源与支持范围

确认目标 Harness、版本、平台、源位置及本次支持的会话行为。用户未指定时，检查官方资料和当前可验证的版本，提出有证据的范围。已有 Adapter 扩展格式时，先核对其当前支持说明和未完成工作。

结合官方源码或文档、受控原生会话样本，回答：

- 如何发现会话；如何取得原始 Project 归属与稳定的 Session、Thread、消息身份？
- 源会追加、重写、分叉、压缩或切换可见路径吗？读取期间如何得到一致视图？
- 用户消息、助手回复、工具、子会话和 usage 分别来自哪些记录？哪些内容只能保留为 Raw，哪些无法支持？

竞品实现用于比较取舍，原生样本用于验证实际格式。记录样本版本、产生方式和覆盖范围；个人历史仅在当前授权范围内读取，入库测试使用受控或脱敏 fixture。

**完成条件：** 支持范围、身份来源和变化语义均有证据，剩余未知已列出影响及最小验证动作。只把改变产品范围、体验或明显成本的选择交给用户；普通技术选择给出理由后自主推进。

## 2. 选择运行时并完成映射

对照 [运行时 Schema](../../../packages/domain/src/collector.ts)，按源行为选择当前能力：

- 使用分页 observation 时，读取 [Codex](../../../docs/adapters/codex.md) 或 [Claude](../../../docs/adapters/claude.md) 中与目标源相近的实现，核对分页重放、cursor 提交与 Raw receipts。
- 需要完整目标及可见成员替换时，评估 source-capture，读取 [捕获与发布合同](../../../docs/architecture/opencode-capture-publication.md)。核对一致源视图、原子激活、独立 Raw 恢复及 Server 前提。

文件或数据库的存储形式本身不决定运行时。为本次支持的内容记录「源记录 → Canonical 身份与更新 → Raw 保留方式 → 读取结果」；对 usage 和子会话同时说明归属，保留未知内容的明确处理方式。

Adapter 封装来源发现、读取和格式语义；归属判定、脱敏、投递、持久进度与恢复复用所选 Host 合同。现有合同无法表达必要行为时，先描述可复现的缺口、影响和拟议扩展，按仓库规则记录决策再实施。

**完成条件：** 所有承诺支持的行为都有映射和对应能力；未支持行为有明确结果；所需 Host/Server 改动和验证边界已识别。

## 3. 打通最小采集闭环

实现一条受控原生会话经生产 Adapter Interface、Collector 和真实 Server 到现有 reader 的路径。以实际源数据核对角色、内容、顺序、身份与 Project 归属，并验证 Search 能定位对应内容。新增共享表示时遵循现有 Canonical/Raw/Search 边界。

尽早把研究结论接入正式实现。最小闭环成立后，按已定范围扩展剩余行为；仅在未知会影响正确性或范围时补充研究。协议探针通过只能证明该探针覆盖的边界。

**完成条件：** 真实采集路径可复现，页面内容与样本对应，关联查询有证据；尚未实现的承诺行为仍明确列为待完成。

## 4. 验证持续采集与恢复

按 [开发验证指南](../../../docs/development.md#verification) 选择现有测试入口，通过调用方实际使用的 Interface 验证。复用已有效的证据，新增测试聚焦本次新增或改变的行为。

| 验证分支 | 必须证明的结果 |
| --- | --- |
| 所有接入 | Git/worktree 或目录归属符合支持范围，其他 Project 被排除，未知归属可诊断；身份稳定，重复采集幂等，失败保留进度，取消释放资源，删除源保留已采集历史 |
| 分页 observation | 多页与未完成记录可继续；失败重放符合 cursor/Raw 提交规则；单源异常与健康源的处理符合合同 |
| source-capture | 源变化不会混入已冻结投递；不完整目标不可见；丢失响应、重启与独立 Raw 恢复遵守激活及 receipt 规则 |
| Raw 开关 | 按 [Raw 策略](../../../docs/cli/raw-capture.md) 验证关闭、重开和部分失败；Canonical 继续，Raw 进度只反映真实确认或合同定义的状态 |
| 声明支持子会话、fork、rewind、compaction 或 usage | 关系、可见成员及统计与原生记录一致；复制前缀的含义明确 |
| 大源、超限与格式不支持 | 分页和内存有界，错误可诊断，已有进度及可见内容得到保留；支持声明不超出实测证据 |

**完成条件：** 每项承诺行为都有通过的对应证据；失败项已修复，或影响范围经明确调整。未验证的平台、版本或原生行为保留为限制。

## 5. 完成安装与产品接入

核对 Adapter manifest、构建输出和独立安装。用隔离 ATAPE_HOME、受控源和测试 Instance 安装实际 tarball，经 CLI 启用并验证采集；包替换后检查进度和实际加载版本。安装不依赖 npm lifecycle scripts 或源码 checkout。

根据目标是官方集成还是自定义包，检查相关入口：

- 官方集成：检查 [工具目录](../../../packages/adapter-catalog/src/index.ts) 及其调用者，接通所需检测、Tools 选择和升级展示。
- 安装与 CI：检查根和 Adapter 的 package scripts、现有验证脚本及工作流。确认新 Adapter 实际被执行；既有 Provider 的全绿不能作为新 Adapter 的证据。
- 官方发布准备：检查 [发布包集合](../../../scripts/release-contract.mjs) 及其打包、校验、上传调用者。按 [发布指南](../../../docs/releasing.md) 处理当前请求授权的交付动作。

更新 Adapter 指南、包说明及 [文档索引](../../../docs/README.md)：支持版本与平台、启用方式、源配置、限制、恢复及所需 Server 能力。复用现有合同链接，合并有效内容后删除过时说明。

**完成条件：** 请求范围内的接入可安装、启用和验证，相关自动化确实包含它，文档支持声明与证据一致。简要报告支持什么、如何启用、验证了什么、剩余限制；实施、合入、发布和部署状态分别据实说明。
